# Project map

Where things are in Pi Pocket, for agents working on it. [index.md](index.md) lists every guide; [AGENTS.md](../AGENTS.md) and [self-editing.md](self-editing.md) have the rules for editing it while it runs; [architecture.md](architecture.md) explains how the parts depend on each other and the orderings they rely on; [features.md](features.md) says what each feature does.

## Processes

`bin/pi-pocket.js` checks Node, then runs `src/launcher/main.ts`. In an npm install, Node strips no types from files in `node_modules`: `bin/strip-types.js` does it for Pi Pocket's own files there, in the launcher and (with `--import`) in the server. The launcher reads its options (`options.ts`), asks how devices connect (`access.ts`: this device, LAN, Cloudflare quick tunnel, Tailscale), runs the server (`src/server/main.ts`) as a child, restarts it on exit code 75 or a crash, and keeps the tunnel up. When a server stops before it is ready while an update from the app is under way, it goes back to the version before: the commit and packages of a git checkout, or the kept copy of a global npm install (`rollBackUpdate` in `src/server/update-state.ts`, the one server module it imports). `term.ts` draws its menu, panel, and QR code in the terminal. The server takes the data folder's lock, opens one `PocketApp`, and serves it with `http.ts`.

## Data (`~/.pi-pocket/`, or `PI_POCKET_DIR`)

- `pocket.sqlite`: Pi Durable's storage: conversations, entries, tasks, and Pi Pocket's documents.
- `config.json`: people, roles, hashed tokens, settings. `push.json`: VAPID keys and push subscriptions. `provider-limits.json`: the limits that runs wait for now, kept only as a hint (a missing or damaged file means no limit is known).
- `uploads/<conversation>/`, `worktrees/` (sessions' git worktrees), `extensions/` (the owner's drop-ins), `themes/` (the owner's theme folders, and `.removed/` for removed ones), `browser/profile/` (the built-in browser's profile; each session's cookies live in memory only).

## Server: `src/server/`

A module split into parts keeps its name for the part others import, with the rest in a folder of the same name beside it (`http.ts` and `http/`, `browser.ts` and `browser/`). Modules import what they use from the module that owns it; there are no barrels. `PocketApp` creates the app's parts and hands each one the app; callers use them as fields (`app.workspace.viewFile(…)`, `app.attribution.requesterOf(…)`).

### Icons

[`web/icon.svg`](../web/icon.svg) supplies the tab, manifest, and notification icon, and is the source for the PNG icons beside it. With `rsvg-convert` installed, regenerate the PNGs from the repository root:

```sh
rsvg-convert -w 180 -h 180 web/icon.svg -o web/apple-touch-icon.png
rsvg-convert -w 192 -h 192 web/icon.svg -o web/icon-192.png
rsvg-convert -w 512 -h 512 web/icon.svg -o web/icon-512.png
rsvg-convert -w 352 -h 352 --page-width 512 --page-height 512 --left 80 --top 80 -b "#13141c" web/icon.svg -o web/icon-maskable-512.png
```

The maskable icon places the 352 × 352 artwork on a 512 × 512 page with 80-pixel margins and a `#13141c` background. Keep these commands outside the SVG: XML comments cannot contain `--`. The icon test in `test/mobile-ui.test.ts` checks that the served SVG decodes as an image.

## How a message travels

1. `POST /api/c/:id/submit` → `commands.submit`: checks access, turns, and spend, expands a template, then `conversation.submit()` with request id `u:<userId>:<clientId>`. The request id makes a retry a no-op and names the author.
2. Pi Durable runs the generation and tool tasks, committing each step to `pocket.sqlite`. Extension hooks run inside those tasks.
3. `app.ts`'s commit coordinator (`#committed`) hears every commit: spend counts usage first, then each document change updates what the app keeps in memory and the rooms that show it, and `attribution.ts` notes who each message is for.
4. Each room sends its tabs what changed. `store.js` applies it, and Preact renders.

## Adding things

- **A document:** define it in `docs.ts`, with `...rebased` so its stored history stays short. To show it live, add it to `ROOM_DOCS` and the view in `room.ts`, and read it in `store.js`.
- **A command:** a method in `commands.ts` (check access first), a route in `http/conversation-routes.ts` (or `http/api.ts` for one that is not about a conversation), an action in `store.js`, then the UI.
- **A sheet:** a component in `web/sheets/`, a case in `sheetBody` (`web/sheets.js`), and `openSheet({ type })` where it opens.
- **Something back should close** (a screen over the conversation, a view that takes another's place on a phone): `useBack(open, close)` from `web/back.js` in the component that shows it. Sheets already have it.
- **A built-in extension:** a file in `extensions/` (its extension named `pocket-…`), its place in `ORDER`, its title in `TITLES`, and its tools in `BUILT_IN_TOOLS` (`reload.ts`), which no test checks.
- **A member of the extension API** (on the host, `web`, `pocket`, or a command's context): add it to `types/pocket.d.ts` with `@since`, and to its page in `docs/extensions/reference/`. `test/public-types.ts` (in `npm run check`) fails until the code and the types agree for the host, `web`, and a command's context; for `pocket`, `extension-ui.test.ts` compares only the members' names, so check its signatures by reading. A host member for built-ins only goes in `Internal` in `public-types.ts` instead.
- **A built-in slash command:** `web/commands.js`, with its name kept from modules' commands in `BUILT_IN_COMMANDS` (`extension-web.ts`).
- **A command of the owner's own:** a drop-in with `web.command`, not a change here ([extensions/commands.md](extensions/commands.md)).
- **A page, rail button, or route that is the owner's own:** a drop-in with a web part, not a change here ([extensions/app.md](extensions/app.md)).

## Rules that are easy to break

- Browsers only see committed state. Nothing is shown before it is stored.
- Document kinds, scopes, and fork settings are stored data: never change them.
- Hooks get only `memo` and `snapshot`. Anything a replay must not repeat goes in a memo or behind an idempotent request id.
- Whose work Pi does comes from request ids (`requests.ts`): a message sent for someone needs their id in its request id; one without it leaves Pi working for whoever it worked for before. At startup, what a crash kept out of the authors document is read back from Pi Durable's records.
- A tool is `replay: "safe"` only if running it twice is harmless.
- Extensions reach the app only through `PocketHost`, and add to it only through `web` (`extension-web.ts`).
- A part of the web app that reaches a side edge of the screen keeps clear of a phone's notch with `var(--inset-l)` and `var(--inset-r)` (`style.css`; the safe-area insets, 0 on most screens). Give the part the inset, not the layout, so its background still runs to the edge.
- Server code is erasable TypeScript with `.ts` imports. Comments are plain sentences.
- The inspector script (`ARTIFACT_INSPECT` in `http/artifact-inspect.ts`) sits in a template string: it has no backtick of its own. The page-to-app Design messages come only from it; the app checks each shape and length and uses the data only as a person's own comment or edit.
- Artifact assets are served only by name from a version's manifest, never by hash, and each response has the sandbox policy and `nosniff`. A private page reaches them with a signed address that lasts 12 hours; never put it in a stored document, a tool result, or a log.

## Tests: `test/`

`npm test` runs every `*.test.ts` with Node's test runner. `helpers.ts` provides a scripted model (`scriptedModel(route)`: `faux-1`, `faux-2`, `faux-vision`), `openApp` (the same data folder again is a restart; `now` moves the clock), `newSession`, `say`, `until`, and `fakeTab`. The scripted model costs nothing: spend tests write `pi.usage` themselves. `browser.test.ts` drives a real Chromium, where one is installed, for the built-in browser, and the `*-ui.test.ts` files load the whole web app in it. `docs-examples.test.ts` loads the example extensions in `docs/examples/` as drop-ins. `extension-web.test.ts` covers extension modules' routes, browser module files, and events, `extension-loader.test.ts` the loader with a real registry, and `extension-ui.test.ts` their browser modules in the app, in Chromium. `memory.test.ts` checks the pending-lesson queue's access and approval safety. `linked-sessions.test.ts` checks linked sessions: a repeated start or send acts once, a hidden origin stays hidden, the checks of whom Pi works for come first, and an unavailable model makes nothing. `gallery.test.ts` checks what the gallery takes from its index: a file name that leaves the extensions folder, a file whose hash differs, an install under a name that was on before (it stays off), a revoked version, and a theme that installs only as pinned and only when its CSS passes the theme check. The notch test in `mobile-ui.test.ts` fakes a notch's safe-area insets in Chromium and checks that the rail, the top bar, and the message box clear it. `turns.test.ts` runs `web/turns.js` in Node: how the transcript groups Pi's answers, and which calls can still run. `voice.test.ts` runs `web/voice.js` in Node with a stand-in speech recognizer: where dictated words land as people type. `hooks.test.ts` covers webhooks and `fence.ts`. The rest of the web app has no tests: check a change to it in a browser, on a copy (`node test/serve.ts`: this folder's code, its own temporary data, a scripted model).
