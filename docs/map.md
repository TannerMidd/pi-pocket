# Project map

Where things are in Pi Pocket, for agents working on it. [index.md](index.md) lists every guide; [AGENTS.md](../AGENTS.md) and [self-editing.md](self-editing.md) have the rules for editing it while it runs; [architecture.md](architecture.md) explains how the parts depend on each other and the orderings they rely on; [features.md](features.md) says what each feature does.

## Processes

`bin/pi-pocket.js` checks Node, then runs `src/launcher/main.ts`. The launcher reads its options (`options.ts`), asks how devices connect (`access.ts`: this device, LAN, Cloudflare quick tunnel, Tailscale), runs the server (`src/server/main.ts`) as a child, restarts it on exit code 75 or a crash, and keeps the tunnel up. `term.ts` draws its menu, panel, and QR code in the terminal. The server takes the data folder's lock, opens one `PocketApp`, and serves it with `http.ts`.

## Data (`~/.pi-pocket/`, or `PI_POCKET_DIR`)

- `pocket.sqlite`: Pi Durable's storage: conversations, entries, tasks, and Pi Pocket's documents.
- `config.json`: people, roles, hashed tokens, settings. `push.json`: VAPID keys and push subscriptions.
- `uploads/<conversation>/`, `worktrees/` (sessions' git worktrees), `extensions/` (the owner's drop-ins), `themes/` (the owner's theme folders, and `.removed/` for removed ones), `browser/profile/` (the built-in browser's profile; each session's cookies live in memory only).

## Server: `src/server/`

A module split into parts keeps its name for the part others import, with the rest in a folder of the same name beside it (`http.ts` and `http/`, `browser.ts` and `browser/`). Modules import what they use from the module that owns it; there are no barrels. `PocketApp` creates the app's parts and hands each one the app; callers use them as fields (`app.workspace.viewFile(…)`, `app.attribution.requesterOf(…)`).

## Extensions: `src/server/extensions/`

Each default-exports `(host: PocketHost, web: ExtensionWeb) => Extension | Extension[] | void` (`web` adds to the app: [extensions/app.md](extensions/app.md)) and is installed in this order: `prompt` (system prompt, with where Pi Pocket's docs are), `artifacts` (artifact tool), `browser` (browser tool and its prompt section; through `host.browsers`), `subagents` (subagent tool and its tasks: anchors, reporters, and the courier that sends waiting reports to the parent together; a subagent runs on its session's model, or one the owner allowed, and the app rebuilds the module when that list changes), `agent-teams` (Agent Teams, off by default: the `team` tool and its prompt section, through `host.linkedSessions`; its browser module `agent-teams.js` describes the tool's calls with `pocket.toolCall`; it imports nothing of Pi Pocket's but types, as a drop-in would), `schedules` (schedule tool; installs the schedule task), `goals` (hook after each answer), `plan` (tool hook and prompt section), `guard` (tool hook that asks for approval), `codemode` (codemode tool; a script's calls go through the same hooks), `memory` (memory tool and the prompt section of lessons in force; through `host.memory`), `pip` (PiP's tools, prompt, and follow task, through `host.pip`; only PiP's conversation selects it, as `PocketApp`'s settings leave it out of every other conversation's), `triggers` (the PR and repository watch tasks and the `watch_pr` tool, through `host.watches` and `host.repoWatches`; webhooks need it on), `gallery` (the extension gallery's owner-only routes under `/api/x/gallery/`, through `host.gallery`, and its twice-daily look for revoked versions; it installs `pocket-gallery`, which tells the web app it is on).

## Web: `web/` (Preact and htm, no build)

Plain ES modules, loaded as they are. `store.js` holds the shared state, and nothing imports in a circle. Some modules do work when they load: `back.js` (it hears back and forward), `store.js`, `ui.js` (Markdown and sanitizer setup, document listeners), `theme.js` (the saved appearance, which `prefs()` reads, and safe mode, `safe-mode.js`, which it imports first), `seen.js` (when this browser last looked at each session), `peeks.js`, `subagents-board.js` (it tells the server while the board shows), `browser-panel.js` and `files-panel.js` (the panels' saved widths), `rich.js` (gives `Markdown` its rich block), `sheets.js` (a step back for each sheet opened from another), `transcript.js` (it hears which answer a jump asked to see), `extension-ui.js` (it loads extensions' browser modules as the server lists them, and hears their events), and `app.js`. `store.set` calls subscribers in the order they subscribed, so keep the order in which modules load when moving code between them.

## How a message travels

1. `POST /api/c/:id/submit` → `commands.submit`: checks access, turns, and spend, expands a template, then `conversation.submit()` with request id `u:<userId>:<clientId>`. The request id makes a retry a no-op and names the author.
2. Pi Durable runs the generation and tool tasks, committing each step to `pocket.sqlite`. Extension hooks run inside those tasks.
3. `app.ts`'s commit coordinator (`#committed`) hears every commit: spend counts usage first, then each document change updates what the app keeps in memory and the rooms that show it, and `attribution.ts` notes who each message is for.
4. Each room sends its tabs what changed. `store.js` applies it, and Preact renders.

## Adding things

- **A document:** define it in `docs.ts`, with `...rebased` so its stored history stays short. To show it live, add it to `ROOM_DOCS` and the view in `room.ts`, and read it in `store.js`.
- **A command:** a method in `commands.ts` (check access first), a route in `http/conversation-routes.ts` (or `http/api.ts` for one that is not about a conversation), an action in `store.js`, then the UI.
- **A sheet:** a component in `web/sheets/`, a case in `sheetBody` (`web/sheets.js`), and `openSheet({ type })` where it opens.
- **Something back should close** (a screen over the conversation, a view that takes another's place on a phone): `useBack(open, close)` from `web/back.js` in the component that shows it. Sheets already have it.
- **A built-in extension:** a file in `extensions/` (its extension named `pocket-…`), its place in `ORDER`, its title in `TITLES`, and its tools in `BUILT_IN_TOOLS` (`reload.ts`), which no test checks.
- **A member of the extension API** (on the host, `web`, `pocket`, or a command's context): add it to `types/pocket.d.ts` with `@since`, and to its page in `docs/extensions/reference/`. `test/public-types.ts` (in `npm run check`) fails until the code and the types agree for the host, `web`, and a command's context; for `pocket`, `extension-ui.test.ts` compares only the members' names, so check its signatures by reading. A host member for built-ins only goes in `Internal` in `public-types.ts` instead.
- **A built-in slash command:** `web/commands.js`, with its name kept from modules' commands in `BUILT_IN_COMMANDS` (`extension-web.ts`).
- **A command of the owner's own:** a drop-in with `web.command`, not a change here ([extensions/commands.md](extensions/commands.md)).
- **A page, rail button, or route that is the owner's own:** a drop-in with a web part, not a change here ([extensions/app.md](extensions/app.md)).

## Rules that are easy to break

- Browsers only see committed state. Nothing is shown before it is stored.
- Document kinds, scopes, and fork settings are stored data: never change them.
- Hooks get only `memo` and `snapshot`. Anything a replay must not repeat goes in a memo or behind an idempotent request id.
- Whose work Pi does comes from request ids (`requests.ts`): a message sent for someone needs their id in its request id; one without it leaves Pi working for whoever it worked for before. At startup, what a crash kept out of the authors document is read back from Pi Durable's records.
- A tool is `replay: "safe"` only if running it twice is harmless.
- Extensions reach the app only through `PocketHost`, and add to it only through `web` (`extension-web.ts`).
- Server code is erasable TypeScript with `.ts` imports. Comments are plain sentences.

## Tests: `test/`

`npm test` runs every `*.test.ts` with Node's test runner. `helpers.ts` provides a scripted model (`scriptedModel(route)`: `faux-1`, `faux-2`, `faux-vision`), `openApp` (the same data folder again is a restart; `now` moves the clock), `newSession`, `say`, `until`, and `fakeTab`. The scripted model costs nothing: spend tests write `pi.usage` themselves. `browser.test.ts` drives a real Chromium, where one is installed, for the built-in browser, and the `*-ui.test.ts` files load the whole web app in it. `docs-examples.test.ts` loads the example extensions in `docs/examples/` as drop-ins. `extension-web.test.ts` covers extension modules' routes, browser module files, and events, `extension-loader.test.ts` the loader with a real registry, and `extension-ui.test.ts` their browser modules in the app, in Chromium. `memory.test.ts` checks the pending-lesson queue's access and approval safety. `linked-sessions.test.ts` checks linked sessions: a repeated start or send acts once, a hidden origin stays hidden, the checks of whom Pi works for come first, and an unavailable model makes nothing. `gallery.test.ts` checks what the gallery takes from its index: a file name that leaves the extensions folder, a file whose hash differs, an install under a name that was on before (it stays off), a revoked version, and a theme that installs only as pinned and only when its CSS passes the theme check. `turns.test.ts` runs `web/turns.js` in Node: how the transcript groups Pi's answers, and which calls can still run. `voice.test.ts` runs `web/voice.js` in Node with a stand-in speech recognizer: where dictated words land as people type. `hooks.test.ts` covers webhooks and `fence.ts`. The rest of the web app has no tests: check a change to it in a browser, on a copy (`node test/serve.ts`: this folder's code, its own temporary data, a scripted model).
